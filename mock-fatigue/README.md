# Стенд FATIGUE-API

Поддельный сервис, отвечающий ровно по контракту из документа
`corpus/source/12-fatigue-api.md`. Нужен затем, чтобы у ассистента появился
источник **живых** данных: правила лежат в вики, а текущие числа — только
здесь.

## Запуск

```
cd mock-fatigue
..\backend\.venv\Scripts\python.exe fatigue_api.py
```

Проверка: `curl http://127.0.0.1:8100/health`
Другой порт: переменная `PW_MOCK_PORT`.

Отдельных зависимостей не нужно — `fastapi` и `uvicorn` уже стоят в
виртуальном окружении бэкенда.

### Почему не `-m uvicorn app:api`

Так было сначала, и это ломалось. `uvicorn модуль:объект` ищет модуль **по
пути импорта**, а не в той папке, откуда запускают. В соседнем `backend`
лежит пакет с именем `app` — и из другого каталога uvicorn поднимал его,
сообщая `Attribute "api" not found in module "app"`. Выглядит как поломка
стенда, на самом деле столкновение имён.

Поэтому файл называется `fatigue_api.py` и запускается напрямую: при прямом
запуске Python берёт файл по имени файла, и вопрос «какой каталог текущий»
не возникает вообще. Файл `app.py` остался пустой обёрткой — его можно
удалить.

Правило на будущее: модуль, который запускают по имени, не должен
называться так же, как пакет в соседнем проекте.

## Что внутри

Парк из 40 труб, генерируется от фиксированного зерна: при каждом запуске
данные одинаковые. Это обязательное условие измеримости — иначе прогон
золотого набора давал бы разные цифры от запуска к запуску, и отличить
«модель стала хуже» от «данные другие» было бы нельзя.

В парке есть трубы во всех трёх состояниях по регламенту РЛ-9.2: ниже 50 %
выработки, между 50 и 80, выше 80.

## Что воспроизведено из контракта намеренно

| Из документа | Как здесь |
| --- | --- |
| `GET /pipes` отдаёт только идентичность, без агрегата ресурса | Так и есть — выработки в реестре нет |
| `E-1108` при неизвестной трубе | Возвращается с HTTP 404 |
| `E-1042` при устаревшем расчёте | Труба `PP-0007`, HTTP 409 и заголовок `Retry-After` |
| `E-2210` при кривом диапазоне шагов | Проверяется в `/trajectory` |
| Разность глубины долота и низа трубы внутри рейса постоянна | Постоянна |
| `lifecycle_event_count` равен нулю у всего парка | `/events` пуст |

Соблазн «добавить агрегат по парку, так удобнее агенту» надо давить.
Отсутствие агрегата — задокументированное ограничение боевого сервиса, и
именно его обходит наш инструмент, вызывая `/passport` по каждой трубе. Стенд,
отвечающий удобнее боевого, не воспроизводит боевых проблем и потому
бесполезен.
