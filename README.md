# PIPEWIKI

Ассистент по внутренней вики инженерного отдела: справочник по документации
шести проектов, отвечающий строго по документам, с проверяемыми цитатами и
честным «в документации этого нет».

Собран как учебный, но не игрушечный проект: каждое решение внутри сделано по
чек-листу LLM-систем, и в коде рядом с решением написано, почему оно такое.
Модель локальная (Ollama), данные не покидают машину.

---

## Что здесь есть

```
pipewiki/
├─ corpus/       16 документов вики: markdown-источники и PDF-выгрузка
├─ backend/      FastAPI: индексация, гибридный поиск, генерация, трейсинг
└─ frontend/     React 19 + TS + Vite + Tailwind по FSD: вики и чат-ассистент
```

Корпус — документация вымышленного отдела вокруг настоящего домена бурильных
труб: PIPEPASS, FATIGUE-API, SURVEYD, TELEMETRY-GW, INSPECT-MOBILE, REPORTD
плюс регламенты, онбординг, постмортемы, глоссарий и FAQ поддержки.

Корпус собран не «чтобы было». В нём намеренно заложено то, на чём ломаются
такие системы: пары вопросов, различающиеся отрицанием (включить/отключить
кэш, можно/нельзя удалить рейс), точные коды и артикулы (`E-1042`, `SVY-409`,
`РЛ-4.2.3`), таблицы, разорванные между страницами, почти дословные дубли
одного абзаца в двух документах, противоречие версий (устаревший порог 70 % в
архивном постмортеме против действующих 80 % в регламенте) и заведомо
отсутствующие темы — чтобы было на чём проверять отказы.

## Требования

- Python 3.11+. На самых свежих версиях (3.14 и новее) часть пакетов может
  ещё не иметь собранных колёс — тогда `pip` будет пытаться собирать их из
  исходников и падать. Если так вышло, поставьте рядом 3.12 и создайте
  окружение на ней: `py -3.12 -m venv .venv`. Проверить, на чём собрано
  текущее окружение: `.\.venv\Scripts\python.exe --version`.
- Node.js 20+ (проверялось на 22) и npm
- [Ollama](https://ollama.com) с двумя моделями:

```bash
ollama pull qwen2.5:14b      # генерация ответа
ollama pull bge-m3           # эмбеддинги, хорошо работает с русским
```

Отвечающая модель меняется одной переменной `PW_OLLAMA_CHAT_MODEL`. На
карте с 16 ГБ памяти четырнадцать миллиардов — потолок разумного: тридцать
уже не влезет целиком и уедет в обычную память.

Выбор сделан не на глаз, а замером. По сравнению с `qwen2.5:7b`
четырнадцатая:

- перестаёт отказываться там, где ответ в документах есть: было четыре таких
  случая на сотню вопросов, стал один;
- реже промахивается ссылкой на документ: было шесть битых, стало четыре;
- почти не делает противоречивых ответов вида «сведений нет» плюс ссылка на
  документ: было шесть, стало два;
- отвечает в полтора раза дольше: 1,6 секунды против 2,5.

Правильность ответов по оценке судьи при этом не изменилась. То есть семёрка
отвечает не хуже — она просто чаще молчит, когда могла бы ответить, и чаще
ссылается не туда. Для справочника это важнее полсекунды, поэтому выбрана
четырнадцатая. На слабой карте семёрка остаётся рабочим вариантом.

Судья для измерений (`nemotron-3.5-lightning`) обязан быть **другой** моделью,
чем отвечающая: модель, проверяющая свои же ответы, систематически их
одобряет.

## Запуск

### 1. Корпус

PDF уже собраны и лежат в `corpus/pdf`. Пересобрать из markdown можно так:

```bash
cd corpus
pip install reportlab
python build_pdf.py
```

### 2. Бэкенд

**Windows, PowerShell:**

```powershell
cd backend
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env

$env:PYTHONUTF8 = "1"
python scripts\ingest.py --dump
uvicorn app.main:app --reload --port 8000
```

**Linux и macOS:**

```bash
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env

python scripts/ingest.py --dump
uvicorn app.main:app --reload --port 8000
```

Три места, где это спотыкается именно на Windows:

1. **`Activate.ps1` не запускается** — «выполнение сценариев отключено в этой
   системе». Разово лечится `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
   Либо обходится без активации вообще: вместо `pip` и `python` звать
   `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` и
   `.\.venv\Scripts\python.exe scripts\ingest.py --dump`.
2. **`PYTHONUTF8=1` обязателен.** Без него скрипты, печатающие русский текст,
   в классической консоли падают с `UnicodeEncodeError`, а в лучшем случае
   выводят кракозябры: `powershell.exe` 5.1 использует кодовую страницу OEM, а
   не UTF-8. Альтернатива — `chcp 65001` перед запуском.
3. **`curl` в PowerShell 5.1 — это алиас на `Invoke-WebRequest`**, а не curl.
   Он принимает другие параметры и иначе печатает ответ. Нужен либо
   `curl.exe`, либо родная команда PowerShell.

Если `python` открывает Microsoft Store вместо интерпретатора — значит
установлена заглушка из магазина; зовите `py` или поставьте Python с
python.org, отметив «Add python.exe to PATH».

Проверить, что живо:

```powershell
curl.exe http://127.0.0.1:8000/api/health
# или: Invoke-RestMethod http://127.0.0.1:8000/api/health | ConvertTo-Json -Depth 5

python scripts\ask.py --search "E-1042"
python scripts\ask.py "как отключить кэш последних значений" --sources
```

Проверить, что видна Ollama и модели на месте:

```powershell
ollama list
curl.exe http://127.0.0.1:11434/api/tags
```

### 3. Фронтенд

Отдельное окно терминала; виртуальное окружение Python здесь не нужно.

```powershell
cd frontend

```

## Что посмотреть глазами в первую очередь

После `ingest.py --dump` в `backend/var/extracted/` лежат три файла на каждый
документ:

- `<DOC>.txt` — что реально извлеклось из PDF;
- `<DOC>.chunks.txt` — как это порезалось на фрагменты, с заголовками;
- `<DOC>.dropped.txt` — какие строки выброшены как колонтитулы.

Сравните `.txt` с исходным markdown в `corpus/source`. Это первый пункт
раздела «Данные и поиск» чек-листа, и он делается не автоматикой, а глазами:
пайплайн не покажет вам разорванную пополам таблицу как ошибку — он молча
проиндексирует мусор.

## Архитектура запроса

```
вопрос
  ├─ проверка: индекс построен той же моделью эмбеддингов, что настроена?
  ├─ эмбеддинг вопроса (bge-m3, нормализованный)
  ├─ гибридный поиск: вектор (dot product) + BM25 (SQLite FTS5)
  ├─ слияние по рангам (RRF, k=60) + дедупликация фрагментов
  ├─ абсолютный порог косинуса — не прошёл? отказ БЕЗ вызова модели
  ├─ контекст по бюджету токенов, лучший фрагмент первым, номера и источники
  ├─ генерация со схемой ответа (statuses / answer / citations)
  │    └─ поток: инкрементальный разбор JSON, наружу — только чистый текст
  ├─ валидация схемы на своей стороне + ДОСЛОВНАЯ проверка каждой цитаты
  └─ события SSE: meta → delta* → answer → done
```

Это цепочка, а не агент: шаги известны заранее и не зависят от промежуточных
результатов. Агент добавил бы недетерминированность, задержку и стоимость, не
добавив ничего — он появится тогда, когда появится настоящее ветвление.

## Измерительный стенд

Всё, что про качество, живёт в `scripts/eval.py`. Прогон сохраняется целиком —
конфигурация и результат по каждому вопросу, — потому что среднее скрывает
структуру: «метрика не изменилась» часто означает «два вопроса починились, три
сломались».

```powershell
python scripts\eval.py validate              # состав набора и различающая сила разметки
python scripts\eval.py search --label base   # прогон поиска, без модели и быстро
python scripts\eval.py answer --label base   # полный прогон с генерацией
python scripts\eval.py judge base            # второй проход: судья-модель
python scripts\eval.py label base --suspect-first   # ручная разметка вслепую
python scripts\eval.py kappa base            # согласие судьи с человеком
python scripts\eval.py compare base new      # два прогона рядом, построчно
```

Что стоит знать до первого запуска:

| команда | зачем |
| --- | --- |
| `noise --runs 3` | три прогона без изменений. Разброс между ними — порог значимости; без него любая дельта это мнение |
| `sweep --rrf-k … --keyword-weight …` | перебор констант слияния по одному прогону, без модели: шесть вариантов стоят как один |
| `recheck <прогон>` | пересчёт дешёвых проверок из сохранённых ответов. Новая метрика появляется и в старых прогонах — иначе сравнивать нельзя |
| `why q034` | разбор поиска по одному вопросу: где нужный фрагмент и почему не первый |
| `sensitivity <прогон>` | порча верных ответов: замечают ли приборы заведомо неверное |
| `diagnose <прогон>` | отличимы ли неотвечаемые вопросы по числам |
| `gate` | набор как тест перед слиянием; допуск равен измеренному шуму |

Три правила, зашитые в стенд и одинаково важные:

**Прочерк и ноль — разные вещи.** Неизмеренная метрика печатается прочерком.
Ноль читается как «всё плохо», прочерк — как «мы этого не мерили», и путать их
значит врать в свою пользу.

**Смена разметки — смена линейки.** `compare` откажется сравнивать прогоны,
посчитанные разной разметкой, и скажет, что делать.

**Инструмент проверяется отдельно.** Судья калиброван на человеке, дешёвая
проверка сверяется с судьёй, разметка проверяется на различающую силу. Прибор
нельзя мерить тем же прибором — на этом проект ловился четырежды.

## Что уже сделано по чек-листу

| Раздел | Сделано |
| --- | --- |
| 0. До первой строки кода | Цепочка вместо агента, локальный контур по требованию к данным, действий с побочными эффектами нет |
| 1. Вызов модели | Температура 0, потолок ответа, стабильная часть промпта сверху, TTFT и скорость генерации меряются раздельно |
| 2. Провайдеры | Единый интерфейс, один HTTP-клиент, раздельные таймауты, повторы только на временных кодах с джиттером и Retry-After, предохранитель, цепочка деградации, рейт-лимит по запросам и токенам |
| 3. Данные и поиск | Чистка колонтитулов, структурный чанкинг с заголовком в тексте, батчевые нормализованные эмбеддинги, версия модели в метаданных индекса с проверкой, идемпотентность по хешу, гибридный поиск с RRF, абсолютный порог, дедупликация, нумерация и бюджет токенов |
| 5. Интерфейс | Поток с буферизованным разбором, «Стоп» рвёт соединение, новый запрос отменяет предыдущий, батчинг по кадрам, явные состояния, схема ответа, отказ как состояние, блок «как получен ответ», без процента уверенности |
| 6. Безопасность | Ключ только на сервере, контент в обёртке «это данные», нейтрализация поддельных разделителей, вывод рендерится как текст, ссылки модели не кликабельны |
| 7. Прод | Трейс на запрос и спан на шаг, маскирование ПД, версия промпта и модели зафиксированы, лимиты, причина остановки всегда названа |

| 4. Измерения | Золотой набор на 113 вопросов с 13 неотвечаемыми, разделённый на настроечную и отложенную части; метрики поиска отдельно от метрик ответа и на уровне чанков; калибровка порога; проверка разделимости; судья-модель вторым проходом, откалиброванный каппой Коэна на ручной разметке; дешёвая проверка факта подстрокой; проверка языка ответа; замер разброса тремя прогонами; перебор констант слияния без повторных прогонов; отпечатки промпта, кода и разметки в конфигурации каждого прогона |

Не сделано и делается дальше: реранкер, переписывание запроса перед поиском,
кэш и запасной провайдер в цепочке деградации (адаптер GigaChat написан, но
выключен), алерты по стоимости и доле непрошедших цитат, канареечная
раскатка, red-team собственной системы. Отдельно отложены пять находок аудита
и отпечаток самого стенда — с объяснением, почему именно отложены.

## Вторая реализация: образец на LlamaIndex

Рядом со своей реализацией лежит та же система, собранная на LlamaIndex из
коробки, — не как замена, а как **измерительный образец**.

Причина одна и неприятная: все цифры проекта получены своим же стендом на
своей же системе. Это замкнутый круг, и разомкнуть его можно только стороной,
которую мы не писали. Если бы готовый фреймворк оказался лучше, это было бы
самое полезное, что могло выясниться.

```powershell
cd backend
pip install -r requirements-alt.txt
python scripts\alt_run.py --label alt1
```

Результат пишется в тот же формат прогона, поэтому дальше работают все
команды стенда: `show`, `compare wide3 alt1`, `sensitivity`, `recheck`.
Зависимости фреймворка в `requirements.txt` не входят сознательно — стенд
обязан запускаться на машине без LlamaIndex.

### Что показало сравнение

Один корпус, один золотой набор, те же модели и та же температура. Обе
колонки посчитаны одной линейкой.

| | образец | наша система |
| --- | --- | --- |
| нужный фрагмент стоит первым (`chunk_top1`) | 0.710 | **0.820** |
| ответ верен по судье (`judge_ok`) | 0.783 | **0.957** |
| ответ на языке корпуса (`language_ok`) | 0.805 | **0.991** |
| задержка, среднее | 2242 мс | **1663 мс** |

Три вывода, каждый с оговоркой:

**Разрыв в поиске — наполовину две константы.** Перебор на своём стеке
(`eval.py sweep`) показал: умолчания библиотеки (`rrf_k` 60, равные веса
списков) дают 0.767 против наших 0.836, то есть **56 % разрыва объясняются
настройками, а не архитектурой**. Остальные 44 % — структурная нарезка,
заголовок внутри куска, порог отсечения, бюджет контекста.

**Каждый пятый ответ образца — не на русском.** 17 китайских и 5 английских
из 113. Встроенный промпт фреймворка английский и языка не задаёт, а
`qwen2.5` — китайская модель, и на коротких вопросах да/нет она уходит в
родной язык. Прибора, который это ловит, в проекте не было — он появился
из-за этой находки.

**У образца нет отказа.** Он отвечает всегда: поэтому верно отвечает на три
вопроса, где наш порог 0.45 отказался зря, и поэтому же выдумывает ответы на
вопросы, которых в корпусе нет. Одна и та же черта даёт ему и лучший, и
худший результат сравнения.

Главная оговорка, без которой таблицу читать нельзя: **сравниваются целые
стеки**, и разница в цифре не говорит, какой слой её создал.

Подробный разбор — в `ШАГ-4-LLAMAINDEX-С-НУЛЯ.md`. Там же пять дефектов,
найденных не в образце, а в собственном измерительном стенде: каждый молча
занижал или завышал цифру, и ни один не ронял тестов.

## Документы проекта

Пять учебных документов, каждый читается с нуля и без предварительных знаний.
Порядок — тот, в котором делалась работа.

| файл | о чём |
| --- | --- |
| `ШАГ-1-С-НУЛЯ.md` | основа: данные, извлечение из PDF, чанкинг, индекс, гибридный поиск, контекст, генерация со схемой, устойчивость вызова, интерфейс |
| `ШАГ-2-ОБЪЯСНЕНИЕ-С-НУЛЯ.md` | измерения: золотой набор, метрики, первый замер и четыре дефекта, которые он вскрыл |
| `ШАГ-2-СУДЬЯ-С-НУЛЯ.md` | судья-модель: зачем нужен, три дефекта в нашем собственном, каппа Коэна |
| `ШАГ-3-АУДИТ-С-НУЛЯ.md` | сплошной аудит кода: 32 находки, 27 правок, пять отложенных с объяснением |
| `ШАГ-4-LLAMAINDEX-С-НУЛЯ.md` | вторая реализация на LlamaIndex как измерительный образец: сравнение двух стеков одной линейкой, разложение разрыва, метрика языка и пять молчаливых дефектов в собственном стенде |

В каждом есть словарик терминов, раздел с готовыми формулировками для
собеседования и короткое саммари в конце каждой части.
