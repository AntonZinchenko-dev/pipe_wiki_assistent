# PIPEPASS — фронтенд: стек, структура, конвенции

## Стек и обоснование выбора

| Слой                 | Выбор                                | Причина                                                                                                    |
| -------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| Ядро                 | React 19, TypeScript 5.7, Vite 6     | —                                                                                                          |
| Серверное состояние  | TanStack Query 5                     | Кэш, инвалидация, фоновое обновление                                                                       |
| Клиентское состояние | Zustand 5 с `subscribeWithSelector`  | Время проигрывания меняется 60 раз в секунду и идёт прямо в three.js и в DOM, не вызывая ререндер React     |
| 3D                   | three.js в императивном классе       | Сцена — один процедурный меш, перекрашиваемый каждый кадр; реконсиляция React здесь только мешает           |
| Стили                | Tailwind CSS 4                       | Токены тем в CSS-переменных                                                                                |
| Локализация          | типизированный словарь-объект        | `zh: Dictionary` роняет компиляцию при пропущенном ключе — полнота перевода гарантируется типами            |
| Моки                 | MSW 2 + генератор кампании           | Один набор обработчиков питает и HTTP-транспорт, и статичное превью                                        |
| Тесты                | Vitest                               | Координаты, минимальная кривизна, единицы, шкалы, соответствие фикстур боевым величинам                    |

## Структура по Feature-Sliced Design 2.1

```
src/
├─ app/       провайдеры, роутер, темы, точка входа
├─ pages/     dashboard · wells · well · pipes · pipe-passport · runs · run-viewer · settings
├─ widgets/   well-scene-3d · pipe-scene-3d · run-playback · rop-profile · fleet-condition
│             damage-profile · ops-timeline · pipe-journey · string-at-step · well-plan
├─ features/  play-run · customize-dashboard · switch-theme · switch-language · switch-units
├─ entities/  pipe · well · run
└─ shared/    api · mocks · lib · ui · i18n · model · config
```

Слой `processes` не используется — он выведен из рекомендаций FSD 2.1.
Направление импортов строго вниз по слоям и проверяется двумя независимыми
инструментами: `steiger` (публичные API слайсов, кросс-импорты) и правило
`eslint-plugin-boundaries` в конфигурации ESLint.

Слайс обязан экспортировать всё наружу через свой `index.ts`. Импорт вглубь
чужого слайса (`entities/pipe/ui`) запрещён линтером. Исключение сделано
только для `shared/**`, где правила `fsd/public-api` и
`fsd/no-public-api-sidestep` отключены сознательно.

## Команды

| Команда                 | Что делает                                                 |
| ----------------------- | ---------------------------------------------------------- |
| `npm run dev`           | Дев-сервер на порту 5173, запросы перехватывает MSW        |
| `npm run build`         | Прод-сборка в `dist/`                                      |
| `npm run build:preview` | Одностраничная сборка в `dist-preview/index.html` без сети |
| `npm run typecheck`     | `tsc -b --noEmit`                                          |
| `npm run lint`          | ESLint 9 flat плюс контроль направления импортов           |
| `npm run lint:fsd`      | Steiger — линтер Feature-Sliced Design                     |
| `npm test`              | Vitest                                                     |
| `npm run check`         | Всё перечисленное подряд — то, что должно быть зелёным в CI |

Пул-реквест не проходит ревью, если `npm run check` красный. Это единственное
жёсткое требование к оформлению.

## Производительность 3D-сцены

Кадр запрашивается только тогда, когда изменились камера, глубина долота,
набор слоёв или сами данные. Метод `setData` считает подпись входа и
игнорирует повторы. Текстура разреза кэшируется по глубине и теме.

Табло рейса, карточка трубы и лента считывателя подписаны на стор напрямую и
пишут в DOM через `ref` — страница при воспроизведении не перерисовывается.

Пропсы сцены обязаны быть стабильными по ссылке. Передача нового объекта на
каждый рендер приводит к полной пересборке меша и падению кадров до единиц.

## Темы и палитра графиков

Плоские графики живут в теме интерфейса: они часть страницы, а не отдельное
окно. Тёмными в обеих темах остаются только трёхмерные сцены — там порода,
разрез и подсветка, и на белом фоне сцена выглядела бы засвеченной
фотографией. Для сцен выделен отдельный набор токенов `--c-viz-*` и класс
`.viz`.

## Сознательные отступления от постановки

1. **Роутинг на `react-router` 7, а не TanStack Router.** Типизированные
   search-параметры вьюера (`?run&t&pipe&layers`) остаются задачей на переезд.
2. **Локализация без i18next.** Словарь-объект даёт автодополнение и
   компиляционную проверку полноты вместо строковых ключей.
3. **3D без react-three-fiber.** Причина в таблице стека выше.
4. **Виртуализация таблиц не подключена.** Реестр обрезан до 400 строк —
   ровно размер боевого парка. При росте ставим `@tanstack/react-virtual`.
