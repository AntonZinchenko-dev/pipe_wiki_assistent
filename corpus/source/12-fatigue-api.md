# FATIGUE-API 1.2.0 — контракт, эндпоинты, коды ошибок

## Что делает сервис

FATIGUE-API считает накопленную усталость бурильных труб по правилу Майнера и
отдаёт паспортные данные по каждой трубе парка. Сервис — источник истины по
ресурсу трубы; все остальные системы, включая PIPEPASS, только читают.

Базовый путь боевого контура — `/api/v1`. Аутентификация — сервисный токен в
заголовке `Authorization: Bearer`, выдаётся по регламенту РЛ-4.2.3.

## Эндпоинты

| Метод и путь                  | Назначение                                                   |
| ----------------------------- | ------------------------------------------------------------ |
| `GET /pipes`                  | Реестр труб. Отдаёт только идентичность, без агрегата ресурса |
| `GET /pipes/{id}/passport`    | Паспорт трубы: идентичность, усталость, сечения               |
| `GET /pipes/{id}/sections`    | Сечения трубы с шагом 1 м, циклы и доля ресурса по Майнеру    |
| `GET /pipes/{id}/runs`        | История работы трубы по рейсам                                |
| `GET /pipes/{id}/trajectory`  | Положение трубы по шагам углубления внутри рейса              |
| `GET /events`                 | Жизненный цикл трубы: инспекции, смена статуса, ремонт        |
| `GET /calculations/{id}`      | Версия расчёта и её параметры                                 |
| `GET /wells`                  | Справочник скважин со сводкой по трубам. Добавлен в 1.2.0     |
| `GET /wells/{id}`             | Одна скважина: состав труб и максимальная выработка           |
| `GET /inspections`            | Инспекции по парку. Фильтры и страницы. Добавлен в 1.2.0      |
| `GET /pipes/{id}/inspections` | История инспекций одной трубы                                 |
| `GET /surveys`                | Версии инклинометрической съёмки: метаданные. Добавлен в 1.2.0|
| `GET /surveys/{id}`           | Одна версия съёмки: дата, причина, сколько труб пересчитано   |
| `GET /runs/{id}/trajectory`   | Траектория всего рейса. Добавлен в 1.2.0                      |

### Параметры `/inspections`

| Параметр   | Значения                              | По умолчанию |
| ---------- | ------------------------------------- | ------------ |
| `category` | `PREMIUM`, `CLASS_2`, `CLASS_3`, `SCRAP` | все        |
| `overdue`  | `true`, `false`                       | все          |
| `limit`    | 1…200                                 | 50           |
| `offset`   | от 0                                  | 0            |

Неизвестное значение `category` — ошибка `E-2210`, а не пустая выборка. Тихо
вернуть ноль строк на опечатку значит сообщить «инспекций такой категории
нет», а это неправда.

### Что означает `category`

`SCRAP` — решение инспектора о списании, принятое по физическому осмотру.
Выработка ресурса к нему отношения не имеет: по расчёту труба не списывается
никогда (см. INSPECT-MOBILE). В парке штатно встречаются трубы с высокой
выработкой и категорией `PREMIUM` и наоборот — это не рассогласование данных.

`overdue` означает, что с прошлой инспекции прошло больше 180 дней. Такая
труба не списывается: она переводится в состояние «инспекция просрочена», к
работе не допускается, но остаётся в парке.

## Ключевые поля ответа

- `critical_local_position_m` — положение самого нагруженного сечения от
  нижнего торца трубы. Именно эта величина определяет состояние трубы;
  повреждения сечений не суммируются.
- `survey_version_id` — идентификатор версии инклинометрической съёмки, на
  которой посчитан результат. Присутствует в каждой строке `/runs` и
  `/trajectory`.
- `end_bit_md_m` и `pipe_bottom_md_m` — глубина долота и глубина низа трубы на
  шаге. Их разность внутри рейса постоянна.
- `miner_damage_fraction` — доля выбранного ресурса, 0…1.
- `cycles_total` — накопленное число циклов по сечению.
- `lifecycle_event_count` — число событий жизненного цикла. На текущей
  кампании равен нулю у всего парка.

## Коды ошибок

| Код      | HTTP | Значение                                                    | Что делать                                                      |
| -------- | ---- | ----------------------------------------------------------- | --------------------------------------------------------------- |
| `E-1042` | 409  | Расчёт для трубы устарел: изменилась версия съёмки           | Дождаться пересчёта, повторять запрос не раньше чем через минуту |
| `E-1108` | 404  | Труба не найдена в парке текущей кампании                    | Проверить идентификатор, не повторять запрос                     |
| `E-2210` | 422  | Некорректный диапазон шагов в запросе траектории             | Исправить параметры `from_step` и `to_step`                      |
| `E-2301` | 429  | Превышен лимит запросов сервисного токена                    | Уважать заголовок `Retry-After`                                  |
| `E-5001` | 503  | Расчётный воркер недоступен                                  | Повторять с экспоненциальной задержкой и джиттером               |

Повторять имеет смысл только `E-2301` и `E-5001`. Коды `E-1108` и `E-2210`
повтором не лечатся: запрос некорректен сам по себе, повтор лишь замедлит
ответ клиенту.

## Чего в API нет, и почему это важно

1. **Сама инклинометрия.** Версии съёмки с 1.2.0 отдаются через `/surveys`,
   но только метаданные: дата, причина уточнения, сколько труб пересчитано.
   Профиля ствола и DLS наружу по-прежнему нет, поэтому 3D-ствола в
   потребителях не будет и после 1.2.0.
2. **Буровые события.** `/events` отдаёт только жизненный цикл трубы, без RPM
   и приращения глубины.
3. **Агрегат усталости по парку.** `/pipes` отдаёт только идентичность. Чтобы
   показать реестр с выработкой ресурса, потребителю приходится звать
   `/passport` на каждую из 400 труб.

Пункт 3 — известная причина, по которой PIPEPASS считает агрегат по парку
локально. Это единственное место, где потребитель отступает от боевого
контракта, и оно задокументировано на обеих сторонах.

Обратите внимание на несимметричность: у `/wells` сводка есть, у `/pipes`
нет. Это не недосмотр. Скважина без состава труб и максимальной выработки не
имеет смысла как сущность, а `/pipes` остаётся реестром идентичности —
менять его поведение значило бы сломать всех, кто на него уже опирается.

## Что изменилось в 1.2.0

Закрыты три из пяти пунктов раздела «чего в API нет»: появился справочник
скважин, метаданные версий съёмки и обратный срез траектории по рейсу.
Добавлены инспекции — единственный эндпоинт сервиса с фильтрами и
постраничной выдачей.

Обратной несовместимости нет: ни один существующий ответ не изменился.

## Лимиты

Сервисный токен ограничен 600 запросами в минуту. Ограничение действует на
токен, а не на IP-адрес, поэтому распараллеливание по нескольким процессам
лимит не обходит. Запрос `/passport` по всему парку (400 вызовов) укладывается
в лимит, но занимает около сорока секунд — потребителям рекомендовано
кэшировать агрегат на своей стороне.
