# REPORTD — сервис отчётов и выгрузок

## Что делает сервис

REPORTD собирает отчёты по кампании и отдаёт их файлами: PDF для печати и
XLSX для дальнейшей работы в таблицах. Данные сервис не считает сам, а
запрашивает у FATIGUE-API и TELEMETRY-GW и только раскладывает по шаблону.

Отчёт строится асинхронно: клиент создаёт задание, получает
идентификатор и забирает готовый файл, когда задание завершилось. Синхронной
генерации нет — на парке 400 труб она не укладывалась в таймаут прокси.

## Типы отчётов

| Код отчёта     | Содержание                                                  | Форматы     |
| -------------- | ----------------------------------------------------------- | ----------- |
| `FLEET_STATE`  | Состояние парка: идентичность, ресурс, критическое сечение   | XLSX, PDF   |
| `RUN_SUMMARY`  | Сводка по рейсу: компоновка, время, ROP, события             | PDF         |
| `PIPE_HISTORY` | История одной трубы по рейсам и скважинам                    | XLSX, PDF   |
| `WELL_PLAN`    | План и факт по скважине с профилем DLS                       | PDF         |
| `INSPECTIONS`  | Журнал инспекций за период                                   | XLSX        |

Отчёт `WELL_PLAN` на боевом контуре недоступен: для профиля DLS нужна
инклинометрия из SURVEYD, а она наружу не выставлена. На демонстрационном
контуре отчёт собирается на фикстурах.

## Лимиты

| Ограничение                        | Значение |
| ---------------------------------- | -------- |
| Одновременных заданий на аккаунт   | 3        |
| Строк в XLSX-выгрузке              | 100 000  |
| Время на одно задание              | 10 минут |
| Срок хранения готового файла       | 72 часа  |
| Размер готового файла              | 40 МБ    |

Задание, не уложившееся в 10 минут, снимается со статусом `TIMEOUT`. Это не
ошибка сервиса: чаще всего причина в том, что запрошен период больше кампании.
Правильная реакция — разбить период, а не повторять то же задание.

Готовый файл удаляется через 72 часа безвозвратно. Повторная генерация того же
отчёта даёт новый файл; гарантии побайтового совпадения с прежним нет, потому
что исходные данные могли быть пересчитаны.

## Коды ошибок

| Код       | HTTP | Значение                                                |
| --------- | ---- | ------------------------------------------------------- |
| `RPT-409` | 409  | Такое задание уже выполняется                           |
| `RPT-413` | 413  | Результат превысил лимит по размеру или числу строк     |
| `RPT-424` | 424  | Источник данных недоступен, отчёт собрать невозможно    |
| `RPT-503` | 503  | Очередь заданий переполнена                             |

Код `RPT-424` всегда означает проблему не в REPORTD, а в источнике: в теле
ответа приходит поле `upstream` с именем недоступного сервиса. Смотреть надо
там.

## Шаблоны

Шаблоны отчётов лежат в репозитории сервиса и версионируются вместе с кодом.
Правка шаблона на работающем сервере через административный интерфейс не
предусмотрена сознательно: отчёт — это документ, который уходит заказчику, и
его вид должен проходить ревью так же, как код.

Смена шаблона не меняет уже выданные файлы. В каждый сгенерированный отчёт в
колонтитул выводится версия шаблона, чтобы по присланному заказчиком файлу
можно было понять, каким кодом он собран.
