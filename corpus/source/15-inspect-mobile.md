# INSPECT-MOBILE — мобильная инспекция труб на базе

## Что делает приложение

INSPECT-MOBILE — приложение для дефектоскописта на трубной базе. Инспектор
сканирует метку трубы, видит её паспорт из FATIGUE-API и заносит результат
инспекции: категорию по API RP 7G, замеры и фотографии.

Платформа — Kotlin Multiplatform: общая бизнес-логика, нативный интерфейс на
Android и iOS. Реально в эксплуатации только Android — на базах используются
защищённые планшеты на Android 11 и новее. Сборка под iOS собирается в CI, но
на устройствах не проверялась.

## Категории инспекции

| Категория  | Значение                          | Действие                      |
| ---------- | --------------------------------- | ----------------------------- |
| `PREMIUM`  | Износ стенки до 20 %              | Допущена без ограничений      |
| `CLASS_2`  | Износ стенки 20…30 %              | Допущена с ограничением по нагрузке |
| `CLASS_3`  | Износ стенки 30…37,5 %            | Только для неответственных операций |
| `SCRAP`    | Износ стенки более 37,5 %         | Списание                      |

Категория проставляется инспектором вручную по результатам замеров. Приложение
её не вычисляет: решение о списании принимает человек, и подменять это
решение расчётом мы не будем.

## Когда труба списывается

Труба списывается, если инспектор проставил категорию `SCRAP`, либо если
обнаружена сквозная трещина или смятие замка независимо от замеров. После
подтверждения списания труба исчезает из активного парка и в реестре
FATIGUE-API больше не появляется.

## Когда труба не списывается

Труба **не** списывается по признаку выработанного ресурса из расчёта
усталости. Доля по Майнеру — расчётная величина, она не заменяет инспекцию.
Даже если расчёт показывает 100 % выбранного ресурса, решение принимается
только по результатам физического осмотра.

Также труба не списывается автоматически при истечении срока с прошлой
инспекции. В этом случае она переводится в состояние «инспекция просрочена» и
не допускается к работе до осмотра, но остаётся в парке.

## Синхронизация с сервером

Инспекция сохраняется локально сразу, отправка на сервер идёт отдельной
очередью. Очередь переживает перезапуск приложения и разряд планшета.

Полноценного офлайн-режима с двусторонним разрешением конфликтов в версии 1.3
нет. Приложение умеет накапливать свои записи офлайн и отправлять их позже,
но если ту же трубу параллельно инспектировали на другой базе, конфликт
разрешается по правилу «побеждает последняя пришедшая запись», и предупреждения
инспектору не показывается. Это известное ограничение, вынесенное в план
работ на версию 2.0.

## Фотографии

Фотография сжимается на устройстве до 1600 пикселей по длинной стороне и
отправляется в объектное хранилище, минуя основной API. В записи инспекции
хранится только ключ объекта. Лимит — 8 фотографий на инспекцию; девятая
фотография не будет принята сервером с ошибкой `IM-413`.

Геометки к фотографиям не пишутся. Причина та же, что и в SURVEYD:
координаты объектов заказчика не покидают периметр, а трубная база — объект
заказчика.
