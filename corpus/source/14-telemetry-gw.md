# TELEMETRY-GW — шлюз телеметрии с буровой

## Что делает сервис

TELEMETRY-GW принимает поток телеметрии с буровых установок, приводит теги к
единому внутреннему словарю и раздаёт подписчикам по WebSocket. Источники
разнородные: часть установок отдаёт WITSML, часть — собственный протокол
подрядчика, часть — файловые выгрузки раз в минуту.

Внутренний словарь тегов — единственное, на что опираются потребители. Имена
тегов источника наружу не выходят никогда: если подрядчик переименует тег у
себя, потребители об этом не узнают.

## Словарь тегов

| Внутренний тег  | Единица | Значение                        |
| --------------- | ------- | ------------------------------- |
| `bit_depth`     | м       | Глубина долота                  |
| `hole_depth`    | м       | Глубина забоя                   |
| `rop`           | м/ч     | Механическая скорость проходки  |
| `rpm`           | 1/мин   | Обороты ротора                  |
| `wob`           | тс      | Нагрузка на долото              |
| `torque`        | кН·м    | Момент на роторе                |
| `spp`           | атм     | Давление на стояке              |
| `flow_in`       | л/с     | Расход на входе                 |
| `block_pos`     | м       | Положение талевого блока        |

Тег `rop` шлюз не берёт от источника, а считает сам по приращению
`bit_depth` за окно 30 секунд. Причина: подрядчики считают ROP по-разному, и
сравнивать их значения между установками бессмысленно.

## Кэш последних значений

Шлюз держит в памяти последнее значение каждого тега по каждой установке.
Подписчик, подключившийся посреди рейса, немедленно получает текущий срез и
только потом — поток изменений. Без кэша интерфейс потребителя оставался бы
пустым до первого изменения каждого тега, а медленные теги меняются раз в
несколько минут.

### Как включить кэш последних значений

Кэш включён по умолчанию. Если он был отключён, включается переменной
окружения на стороне шлюза:

```
TG_SNAPSHOT_CACHE=on
TG_SNAPSHOT_TTL_S=900
```

После включения требуется перезапуск процесса шлюза: значение читается один
раз при старте. Проверить, что кэш работает, можно эндпоинтом
`GET /internal/snapshot/{rig_id}` — он отдаёт текущий срез из памяти.

### Как отключить кэш последних значений

Отключать кэш штатно требуется в одном случае: при отладке источника, когда
нужно видеть только реальные приходящие пакеты, а не срез из памяти.

```
TG_SNAPSHOT_CACHE=off
```

Отключение кэша в продакшене запрещено. Подписчики рассчитывают на срез при
подключении, и без него интерфейсы показывают пустые табло, что операторы
воспринимают как аварию связи. Если кэш нужно отключить на боевой установке
для отладки, это делается через окно обслуживания и с уведомлением
супервайзера смены.

## Коды ошибок

| Код      | Значение                                                     |
| -------- | ------------------------------------------------------------ |
| `TG-401` | Источник не прошёл аутентификацию                            |
| `TG-409` | Пакет с временем раньше уже принятого — отброшен как поздний  |
| `TG-413` | Пакет превышает 256 КБ                                       |
| `TG-503` | Очередь публикации переполнена, поток приторможен            |

Код `TG-409` в норме встречается: файловые источники повторно присылают
перекрывающиеся окна. Тревожным считается не сам факт, а доля таких пакетов
выше 5 % от потока установки.

## Задержка

Целевая задержка от прихода пакета до доставки подписчику — не более 800 мс
на девяносто пятом процентиле. Реально достигаемая на WITSML-источниках —
около 300 мс, на файловых — до 70 секунд, потому что источник сам выгружает
данные раз в минуту. Файловые источники помечены в интерфейсе как
«с задержкой», чтобы оператор не считал устаревшее значение текущим.
